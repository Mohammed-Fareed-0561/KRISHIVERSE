# KrishiVerse Documentation

Project docs live here, grouped by area. The two landing READMEs stay in place:
`../README.md` (project overview) and `../KRISHIVERSE/README.md` (frontend package).

| Folder | Contents |
|---|---|
| `architecture/` | PRD, system/UI/UX/backend design, master prompt, overview, technical audit |
| `chatbot/` | Chatbot behaviour and improvements |
| `crop-doctor/` | Reasoning/prediction-to-advice layer behind disease diagnosis |
| `weather/` | Weather API fixes and test notes |
| `rag-knowledge-base/` | RAG guides, rag_service docs, agricultural dataset blueprints |
| `knowledge-base/` | Offline architecture, dataset architecture, agriculture guide |
| `setup/` | Startup guides, quick reference, Windows commands |
| `testing/` | Checklists (incl. phone QA), test notes |
| `troubleshooting/` | Troubleshooting guide |
| `history/` | Historical fix logs (point-in-time records, kept for reference) |
| `project/` | Phase status, MSME documentation, documentation index |
| `frontend/` | Frontend optimisation notes |
| `evaluation/` | AI architecture audit, evaluation report, Laya integration |
| `auth/` | Farmer authentication: architecture, routes, sessions, offline profile sync, security controls |
| `onboarding/` | Six-step pilot onboarding wizard, offline progress, funnel telemetry |
| `admin/` | Admin observability: architecture, telemetry schema, metrics catalog, security, farmer analytics, runbook |

Note: `KRISHIVERSE/tests/fixtures/kb-ingestion/diseases.md` is a test fixture
and stays with the tests. `plans/` (planning tool state) is untouched.
